생각을 문서로 맞추는 법

요약 · 이 홈의 설명은 원문을 길찾기용으로 정리했습니다.

이 저장소는 agent 기능 목록이 아니라, 저자가 현재 상태와 권위를 확인하고 좁은 계약으로 일한 뒤 증거와 독립 검토로 결과를 닫는 방식을 설명합니다.

저자가 먼저 확인하는 것

  1. 현재 상태추측보다 Git·테스트·실행 상태
  2. 권위질문별 최종 판단 근거
  3. 계약목표·범위·금지·완료 조건
  4. 증거주장에 맞는 확인 자료
  5. 독립 검토중요한 위험에만 추가
  6. 이어가기다음 세션이면 현재 상태를 HANDOFF

이 저장소를 읽는 순서

  1. 여기서 시작 · 처음 이해하기목적, 용어, 전체 지도
  2. 기반 다지기권위·작업 계약·검증 증거
  3. 워크플로작업 흐름과 단계별 경계
  4. 도구와 역할목적에 맞는 도구 선택
  5. 예시와 템플릿실제 문서 형태 확인
  6. 평가 근거이해도와 완전성 검증

사람에게 남는 결정

  • 제품 목표와 사용자 계약
  • 현재 제품·설계 권위의 선택
    delivery plan은 실행 순서를, archive는 과거 이력을 다루며 제품 판단을 덮어쓰지 않음
  • 중요한 선택의 장단점과 경계
  • commit·push·merge 같은 외부 효과

핵심 교정: reviewer는 문서가 기준을 만족하는지 평가합니다. 사용자의 제품 결정을 대신하지 않습니다.

설계 정렬과 집중 질문 읽기

머릿속 의도를 문서 권위로 옮기는 과정

Grilling은 사람을 공격하는 심문이 아닙니다. 한 번에 하나의 모호함을 질문해 사용자의 암묵적 의도·전제·우선순위를 밖으로 꺼내고, 문서에 반영한 뜻을 사용자가 다시 확인하는 과정입니다.

  1. 현재 권위 확인어느 설계 문서가 판단하는가
  2. 질문 하나용어·상태·경계 충돌 좁히기
  3. 사람이 결정“A이고 B는 아니다” 확인
  4. 권위 문서 반영결정된 뜻을 기준에 기록
  5. 되짚기·독립 검토사용자 확인과 충돌·누락 검증
  6. 정합 후 멈춤관련 문서까지 맞춤 / 작은 가역 선택은 생략

텍스트 흐름: 질문에 맞는 현재 product/design 권위를 먼저 찾는다 → 한 번에 하나의 좁은 질문으로 용어·상태·경계 충돌을 드러낸다 → 중요한 뜻은 사람이 결정한다 → 결정된 뜻을 권위 문서에 반영한다 → 작성자가 “A이고 B는 아니다”로 다시 설명하고 사용자가 확인한 뒤 독립 reviewer가 충돌·누락·반례와 관련 문서·schema·example의 정합성을 검증한다 → 충돌과 High·Medium finding이 해소되면 멈춘다. 작은 reversible 선택에는 전체 grilling을 생략한다.

관점별로 함께 읽을 경계

실무자 · 결과test·diff·runtime으로 검증된 결과와 commit·push·merge·deploy로 적용된 결과는 별개다. 실무자 · 재개HANDOFF는 현재 이어갈 상태, MEMORY는 다시 쓸 장기 교훈이다. 제품 · 실행 전메타프롬프팅은 요청을 정제하며 구현을 실행하지 않는다. 제품 · 권위현재 product/design 문서가 제품 권위다. delivery plan은 실행 순서를, archive는 과거 이력을 다루며 현재 제품 판단을 덮어쓰지 않는다.
