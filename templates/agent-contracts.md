# LLM 에이전트 작업 계약 템플릿

프로젝트와 도구에 맞게 복사해서 사용한다. 모든 항목을 채울 필요는 없지만, 범위와 완료 조건은 생략하지 않는 편이 좋다.

## 구현 계약

```markdown
## 목표
[사용자에게 생겨야 하는 결과]

## 현재 근거
- Issue/요구사항: [링크 또는 파일]
- 설계 권위: [파일]
- 현재 branch/worktree: [확인 필요]

## 허용 범위
- 수정 가능: [경로]
- 수정 금지: [경로 또는 외부 상태]
- 관련 없는 리팩터링 금지

## 완료 조건
- [관찰 가능한 동작]
- [실패/경계 조건]
- [필수 테스트 또는 증거]

## 보고 형식
- 변경 파일
- 실행한 검증과 결과
- 남은 위험 또는 차단 요소
```

## 독립 리뷰 계약

```markdown
## 역할
당신은 구현자와 독립된 리뷰어다.

## 검토 근거
- 요구사항: [Issue/문서]
- 변경 범위: [commit/diff]

## 경계
- 저장소를 수정하지 않는다.
- 지정된 목적과 diff만 검토한다.
- 스타일 선호나 무관한 개선은 finding으로 만들지 않는다.

## 판정
- ACCEPT: 구체적인 결함이 없다.
- REVISE: 범위 안의 수정으로 해결할 수 있다.
- REJECT: 요구사항 또는 설계와 근본적으로 충돌한다.

## 출력
심각도순 finding. 각 finding에 위치, 영향, 근거, 최소 수정 방향을 포함한다.
```

## Handoff 계약

```markdown
# HANDOFF

## 목표
[전체 목표]

## 현재 상태
- 저장소/branch/HEAD:
- 완료된 작업:
- 아직 완료되지 않은 작업:

## 검증 증거
- 실행한 명령:
- 결과:
- 리뷰 결과:

## 보호할 사용자 변경
- [추적되지 않았거나 별도 보존해야 할 파일]

## 다음 작업
1. [가장 작은 다음 단계]
2. [그다음 단계]

## 차단 요소와 필요한 결정
- [없으면 없음]
```

## 병렬 작업 DAG 계약

```markdown
## Baseline
- 모든 lane이 의존하는 선행 작업

## Parallel-ready lanes
- Lane A: 목표 / 허용 경로 / 검증 / 리뷰어
- Lane B: 목표 / 허용 경로 / 검증 / 리뷰어

## Sequential lanes
- Lane C는 A merge 후 rebase 필요: [이유]

## Decision-blocked
- 사용자 또는 제품 결정이 필요한 항목: [질문]

## Merge gate
- 각 lane 독립 테스트 및 리뷰 통과
- 최신 main rebase
- 공유 smoke 재실행
- CI 통과
```
