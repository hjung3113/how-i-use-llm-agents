# 독립 리뷰 브리프

## 목표

이 저장소가 한 고급 LLM 에이전트 사용자의 실제 작업 방식을, 회사의 Claude Code 입문자부터 중상급 사용자까지 이해할 수 있게 설명한다. 독자는 먼저 “이 사람은 왜, 언제, 어떤 단계로 agent를 쓰는가”를 정확히 재구성하고, 그다음 자신의 프로젝트에 필요한 부분만 적용할 수 있어야 한다.

## 필수 내용

- 초급, 중급, 고급 사용 방식
- 공통 운영 파일과 범용 rule 예시
- 자주 사용하는 워크플로우 패턴
- 다양한 하네스 형태와 선택 기준
- 실제로 자주 사용하는 오픈소스 skill/plugin 범주
- 핵심 개념과 독립 검증 방식
- 복사 가능한 작업 계약
- 자주 사용하는 `docs/` 구조와 각 문서의 목적·수명·권위
- 15분 quickstart와 초보→중급→고급 학습 경로
- 실제 세션 재분석에서 발견한 추가 공통 패턴
- 적용 방법보다 먼저 이해할 수 있는 핵심 이야기와 입문용 용어집
- 공개 Meta-Prompt 사례의 사용 시점, 승인 흐름, Fresh Run 경계
- 제품 설계를 여러 문서로 나누는 장단점, 기준, 규모별 예시

## 경계

- private 프로젝트, 로컬 경로, credential을 노출하지 않는다. 사용자가 출처로 지정한 공개 저장소는 명시적인 설계 근거로 링크할 수 있다.
- 특정 모델이나 도구를 유일한 정답처럼 마케팅하지 않는다.
- 작은 작업에 과도한 다중 에이전트 구조를 요구하지 않는다.
- 제품 설계, delivery 계획, 현재 실행 상태, 장기 memory를 구분한다.
- 실제 프로젝트 구조를 예시로 사용하되 공개 저장소와 일반화된 패턴만 인용한다.

## 리뷰 요청

`docs/90-evaluation/evaluation-rubric.md`와 `docs/90-evaluation/review-criteria.md`의 관점으로 전체 저장소를 적대적으로 검토한다. 문서나 저장소는 수정하지 않는다. 서로 다른 숙련도의 독자가 저자의 실제 사용 방식을 정확히 이해하는지 먼저 확인하고, 적용 가능성은 두 번째로 본다. 구체적인 문제만 심각도순으로 보고하고 마지막에 `ACCEPT`, `REVISE`, `REJECT` 중 하나를 판정한다.
