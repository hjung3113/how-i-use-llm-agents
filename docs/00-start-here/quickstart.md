# 15분 Quickstart

목표는 Claude Code 설치 설명을 반복하는 것이 아니라, 이미 회사 환경에서 사용할 수 있다는 전제 아래 **읽기 → 작은 수정 → 검증**을 안전하게 경험하는 것이다. 설치와 로그인은 [Anthropic 공식 시작 문서](https://docs.anthropic.com/en/docs/claude-code/getting-started)를 따른다.

## 0–3분: 안전한 저장소 선택

- 자신이 이해하는 작은 프로젝트를 선택한다.
- 중요한 미커밋 변경이 없는지 `git status`로 확인한다.
- 처음에는 production credential이나 고객 데이터가 필요한 저장소를 피한다.
- 회사의 보안·데이터·허용 도구 정책을 먼저 따른다.

## 3–6분: 최소 운영 파일 추가

Claude Code만 쓴다면 루트에 다음 `CLAUDE.md` 하나를 둔다.

```markdown
# CLAUDE.md

작업 전에 현재 Git 상태와 관련 파일을 확인한다.
기존 사용자 변경을 보존하고 요청 범위만 수정한다.
수정 후 가장 관련 있는 테스트와 diff를 확인한다.
commit, push, PR, merge는 명시적으로 요청된 단계만 수행한다.
검증하지 못한 부분을 완료라고 표현하지 않는다.
```

Codex 등 여러 agent가 같은 규칙을 공유한다면 위 공통 규칙을 `AGENTS.md`로 옮기고 `CLAUDE.md`를 다음처럼 줄인다.

```markdown
# CLAUDE.md

작업 전에 루트 AGENTS.md를 읽고 따른다.
CONTEXT.md가 있으면 제품 목적과 권위 문서를 확인한다.
재개 작업이고 HANDOFF.md가 있으면 읽은 뒤 현재 Git 상태를 다시 검증한다.
```

이것이 15분 과정의 명시적인 두 파일 variant다. 전체 예시와 각 optional 파일의 생성 시점은 [project operating system](../../examples/project-operating-system/README.md)에 있다.

## 6–9분: 읽기 전용 탐색

Claude Code를 프로젝트 루트에서 실행하고 요청한다.

```text
아직 파일은 수정하지 마.
이 프로젝트의 목적, 실행 방법, 테스트 방법, 주요 모듈을 확인해.
확인한 파일을 근거로 설명하고 모르는 것은 모른다고 표시해.
```

확인할 것:

- 실제 파일을 읽었는가?
- 실행 명령을 추측하지 않고 설정 파일에서 찾았는가?
- 프로젝트의 미커밋 변경을 인지했는가?

## 9–13분: 작은 변경

README 오타, 좁은 테스트 추가, 명확한 validation처럼 되돌리기 쉬운 작업을 고른다.

```text
[관찰 가능한 목표]를 수정해.
[허용 파일]만 변경하고 관련 없는 정리는 하지 마.
수정 후 [검증 명령]을 실행하고 변경한 파일과 결과를 알려줘.
commit이나 push는 하지 마.
```

## 13–15분: 직접 확인

```text
git diff를 다시 읽고 요청과 무관한 변경이 없는지 확인해.
실행한 테스트, 실행하지 못한 테스트, 남은 위험을 구분해서 보고해.
```

사람도 diff와 test 결과를 확인한다. 마음에 들지 않으면 전체 재작성을 시키기보다 정확한 finding을 준다.

## 완료 체크

- [ ] Claude가 저장소를 읽고 근거 파일을 제시했다.
- [ ] 변경 범위가 요청과 일치한다.
- [ ] 관련 test 또는 검증을 실행했다.
- [ ] diff에 예상하지 않은 변경이 없다.
- [ ] 원격 상태를 바꾸지 않았다.

이 다섯 항목이 통과하면 첫 성공이다. 다음에는 [기본 정신모델](mental-model.md)로 이동한다.
