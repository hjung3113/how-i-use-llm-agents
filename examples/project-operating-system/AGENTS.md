# AGENTS.md

이 저장소에서 작업하는 모든 LLM 에이전트가 지켜야 할 공통 규칙이다.

## 시작할 때

- 현재 `AGENTS.md`, `CONTEXT.md`, 관련 설계 문서와 Issue를 확인한다.
- `git status`, branch, HEAD를 확인하고 기존 사용자 변경을 식별한다.
- `HANDOFF.md`와 memory는 탐색 단서로만 사용하고 변할 수 있는 상태는 다시 검증한다.
- 요구사항이 충분히 명확하면 안전한 범위 안에서 진행하고, 결과를 크게 바꾸는 선택만 질문한다.

## 작업 범위

- 현재 요청과 acceptance criteria에 직접 필요한 최소 범위만 변경한다.
- 관련 없는 리팩터링, 새 의존성, 추측성 추상화를 추가하지 않는다.
- 하위 디렉터리에 별도 `AGENTS.md`가 있으면 그 영역에서는 추가 규칙을 적용한다.
- 생성 파일보다 권위 있는 원본을 수정한다.

## 안전

- 추적되지 않았거나 관련 없는 사용자 파일을 삭제, 덮어쓰기, stage하지 않는다.
- 비밀값, 개인정보, credential을 코드·로그·memory에 기록하지 않는다.
- 로컬 commit은 요청된 작업을 기록하는 범위에서만 수행한다. push, PR, merge, 배포, Issue 종료처럼 원격 또는 다른 사람에게 영향을 주는 변경은 사용자 승인 범위 안에서만 수행한다.
- 파괴적 작업은 정확한 대상을 먼저 확인하고 가능한 경우 복구 가능한 방법을 사용한다.

## 구현과 검증

- 버그 수정은 가능하면 실패를 재현한 뒤 원인을 설명한다.
- 변경 위험에 비례한 가장 좁은 테스트부터 실행한다.
- 테스트 통과만으로 요구사항 충족을 추정하지 말고 경계 조건과 실제 diff를 확인한다.
- UI 변경은 가능하면 실행 중인 서비스와 실제 사용자 경로에서 확인한다.
- 검증하지 못한 부분은 완료라고 표현하지 않는다.

## 보고

- 결과를 먼저 말하고 변경 파일, 검증 결과, 남은 제한을 간결하게 적는다.
- 현재 상태와 과거 기록, 확인된 사실과 추론을 구분한다.
- 다음 세션이 필요하면 `HANDOFF.md`에 재개 가능한 상태를 남긴다.
